# Project rules

- Citizen pages live under `/app/*`, inspector pages under `/inspector/*` (role-gated in `_authenticated/inspector.tsx`); `/dashboard` redirects by role. Why: one auth gate, two clear areas.
- Roles live only in `public.user_roles` (`admin`, `inspector`); the first account ever created becomes admin+inspector via the `handle_new_user` trigger. Why: prevents privilege escalation and bootstraps the first admin.
- All staff writes (status, notes, classification, team, roles) go through SECURITY DEFINER RPCs that check `is_staff`/`has_role`; citizens have only SELECT/INSERT. Why: status history and notifications are always written together and cannot be bypassed.
- Complaint references are generated by a DB trigger; citizen inserts are sanitised in `complaints_before_insert`. Why: users cannot forge status, AI fields or references.
- Resolving requires a resolution note and at least one after-repair photo (enforced in `set_complaint_status`). Why: resolution must be an explicit, evidenced action.
- Photos go to private bucket `complaint-photos` at `<complaint_id>/<file>` and are shown via signed URLs. Why: complaint photos are private.
- AI detection runs in `src/lib/ai-analysis.functions.ts` against an external FastAPI server (`AI_DETECTION_URL`, optional `AI_DETECTION_API_KEY`); when unset or failing, the complaint is marked "AI analysis unavailable" — never fabricate predictions. Severity scoring is the documented pure function in `src/lib/severity.ts` (tested).
- Leaflet maps are loaded only via the lazy wrappers in `src/components/map/Maps.tsx`. Why: Leaflet touches `window` at import time and would break SSR.
- Demo rows are seeded with `is_demo = true` and must stay visibly labelled.
- Notifications are in-app only; never show "email/SMS sent" unless a provider is actually wired.
